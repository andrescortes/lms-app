# Learning API Constitution

## Core Principles

### I. Pure-Go Static Build (NON-NEGOTIABLE)
Every build MUST produce a statically linked binary compiled with `CGO_ENABLED=0` against Go
1.23 or newer. Builds MUST NOT link any C library or require a C toolchain at runtime. The HTTP
layer MUST be built on `github.com/go-chi/chi/v5` using standard `net/http` handlers
(`http.HandlerFunc`). All request logging MUST be structured via `log/slog`, and every log line
MUST carry a `request_id` correlation field. Rationale: a reproducible single-binary deployment
removes runtime dependency drift and keeps container images trivial.

### II. Clean Architecture With One-Way Dependencies (NON-NEGOTIABLE)
Dependencies MUST flow strictly inward: `internal/domain` → `internal/usecase` →
`internal/adapter/*`, with `cmd/api` as the composition root. `internal/domain` MUST import only
the Go standard library; it MUST NOT import `net/http`, `database/sql`, chi, or `jwt`.
`internal/usecase` MUST accept `context.Context` as its first argument and MUST define small
consumer-side repository/broker interfaces. `internal/adapter/sqlite`, `internal/adapter/http`,
`internal/adapter/security`, `internal/adapter/realtime`, and `internal/adapter/redis` MUST hold
all concrete infrastructure. `cmd/api/main.go` MUST wire dependencies and MUST perform graceful
HTTP shutdown.

### III. SQLite Durability And Schema Discipline (NON-NEGOTIABLE)
All persistence MUST use the pure-Go `modernc.org/sqlite` driver with DSN PRAGMAs
`journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, and `busy_timeout=5000`; write
pools MUST set `SetMaxOpenConns(1)` to prevent `SQLITE_BUSY`. Migrations MUST be managed with
`goose` under `db/migrations/`, MUST use `STRICT` tables, ISO-8601 UTC `TEXT` timestamps,
`INTEGER` booleans (`0`/`1`), and `CHECK (json_valid(...))` on JSON columns. Query code MUST be
generated by `sqlc generate` (`engine: "sqlite"`, `db/queries/` → `internal/adapter/sqlite/sqlcgen/`).

### IV. Local Security And Contract Validation (NON-NEGOTIABLE)
Incoming JWTs MUST be verified locally with `github.com/golang-jwt/jwt/v5` using
`jwt.WithValidMethods([]string{"HS256"})` and the `JWT_SECRET` environment variable; verification
MUST extract `sub` and `role` and MUST NOT call `identity-service` on the hot path. Exercise JSON
payloads MUST be validated against the JSON Schemas in `shared/contracts/exercise-schemas/` using
`github.com/santhosh-tekuri/jsonschema/v6`.

### V. Realtime Integrity And Bounded Lifecycles (NON-NEGOTIABLE)
SSE brokers MUST guard shared state with `sync.RWMutex` and MUST issue single-use Redis-backed
`/sse-ticket` tokens. Live quiz WebSockets MUST use `github.com/coder/websocket` with exactly one
dedicated goroutine loop per room and MUST clean up on `r.Context().Done()`.

## Section 2: Technology Stack And HTTP Contract Constraints

- HTTP handlers MUST be standard `net/http` `http.HandlerFunc` values; routing MUST use chi.
- HTTP middlewares MUST be composable chi middlewares named `Authenticate`, `RequireRole`, and
  `RequireCourseOwner`.
- Errors MUST use a centralized JSON envelope with fields `code`, `message`, `timestamp`, and
  `path`, produced by `respondError(w, r, err)`.
- Database file locations: `/data/learning.db` in prod, `./data/learning.db` in dev, `:memory:`
  in tests.
- The OpenAPI contract at `shared/contracts/learning-api.yaml` MUST stay synchronized with the
  implemented handlers.

## Section 3: Development Workflow, Testing And Quality Gates

- Tests MUST use Go's standard `testing` package exclusively (no `testify`), MUST be table-driven,
  and MUST cover `:memory:` SQLite integration and `httptest` endpoint tests.
- Every slice MUST pass `sqlc generate && git diff --exit-code`, `golangci-lint run`, and
  `go test -race ./...` before merge.
- Agent Token Discipline: produce minimal delta edits, never rewrite unrelated files, keep the
  OpenAPI spec synchronized, and use Headroom MCP tools (`headroom_compress`, `headroom_retrieve`)
  when inspecting large generated files or verbose outputs.

## Governance

This constitution supersedes all other development practices for learning-api. Amendments MUST be
proposed in writing, reviewed, and accompanied by a migration plan for any affected slice.
Versioning follows semantic rules: MAJOR = backward-incompatible governance/principle removal or
redefinition; MINOR = a new principle/section or materially expanded guidance; PATCH =
clarifications, wording, typo fixes, and non-semantic refinements. All pull requests and reviews
MUST verify compliance with these principles. Complexity MUST be justified against them. Runtime
development guidance is drawn from `.specify/templates/` and the companion extension commands.
